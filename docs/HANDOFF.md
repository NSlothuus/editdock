# Implementation handoff — 0.3.0-alpha.1

## Surfaces and trust

- Browser bundler: `import { EditWeave, EditorSession, ... } from '@rapid42/editdock'`. `EditWeave` extends `HTMLElement`; never import this root entry into Node without a DOM. Assign `storage: HostStorage` before mounting, await `ready`, and handle project changes/saves in the host.
- `HostStorage.load(): Promise<Project | null | {project: Project | null, accept(): void}>`; `save(Project): Promise<void>`; `ingest(File, Kind): Promise<Asset>`; optional `export(Project): Promise<string>` and `supportsExport?: boolean`. `accept()` applies a response-specific CAS/load token only after the SDK accepts the project. Host must maintain real authorization, media custody, accurate probed durations/audio facts, asset URLs, atomic project writes and conflict handling. `LocalAPIStorage` endpoints are illustrative host contracts, not a shipped server; `BrowserProjectStorage` still delegates ingest/export to host endpoints.
- Node-only `import { renderMP4 } from '@rapid42/editdock/render'`. Caller supplies a validated project, asset resolver, owned work/output paths, a trusted FFmpeg executable, timeout and cancellation policy. Do not mix the browser root with Node rendering. Neither SDK nor package authenticates users or exposes an HTTP upload service.
- CLI `editdock help`, `schema`, `doctor --ffmpeg /abs/path`, `project init --output /abs/new.json`, `project validate --project /abs/project.json`, `project apply --project /abs/project.json --commands /abs/commands.json --output /abs/new.json`, `render --project /abs/project.json --manifest /abs/manifest.json --output /abs/new.mp4 --ffmpeg /abs/path`. Commands print a single versioned JSON object on stdout, status/diagnostics on stderr; nonzero exit and typed JSON error on failure. Exit codes: 0 success, 2 usage, 3 invalid input, 4 missing prerequisite, 5 output conflict, 6 cancellation, 7 uncertain lifecycle/publication or committed publication reported after interruption. Inspect `schema` before issuing typed edits. Manifest format: `{ "version": 1, "assets": { "asset-id": "/absolute/admitted/source.mp4" } }`, exact asset IDs. CLI input files are bounded regular files; source paths require trusted local custody.

## Executable smoke

Run `node scripts/quickstart.mjs --bin /absolute/path/to/editdock --ffmpeg /absolute/path/to/ffmpeg --ffprobe /absolute/path/to/ffprobe --output-dir /absolute/path/to/nonexistent-dir`. It generates **real** 60-frame 30-fps H.264 source media, probes its frame count and audio facts, initializes/validates a project, applies typed asset+clip, four-frame trim, title and manual caption, renders a 60-frame 960×540 H.264/AAC MP4, and strictly decodes video and audio. The source URL in the generated project is only an illustrative host URL; the manifest explicitly maps its ID to the local generated source. Do not copy generated/project metadata to production media; probe and admit your actual files. This test retains render stage for inspection, not automatic cleanup.

## Publication, failures, limitations

CLI project outputs use create-only writes, and render output uses a private sibling stage plus create-only publication. Never retry into an occupied output; choose a fresh directory/name. Retained stages may contain source media. On `PUBLICATION_UNCERTAIN`, `RENDER_PUBLICATION_COMMITTED`, or `RENDER_LIFECYCLE_UNCERTAIN`, inspect the target and retained stage before retrying; do **not** blindly delete or overwrite either. A failed/cancelled render may retain stage even when no final target exists. Keep credentials/private media out of issue reports and CI logs.

Fixed 30 fps, 960×540 H.264/AAC export; no transcription, automatic captions, arbitrary FFmpeg filters, general media ingest server, unbounded lane count, or stability promise. macOS arm64/Node 26.7 with caller-provided FFmpeg and ffprobe was the referenced local test combination; Linux/other OS and alternate codec builds remain unqualified. `doctor` checks availability and reports a reference combination, not an independently verified platform certification. Hosts/distributors supply FFmpeg and comply with its build-specific licensing; none is bundled.

## Upgrade discipline

Pin the exact SDK version and commit the application lockfile; do not use `^`, `latest` or mutable prerelease tags in deployment. Alpha tags must be immutable; fixes get a new version and a new reviewed tarball. Before upgrading, snapshot each project and its media/asset mapping to host-owned storage, verify the snapshot can be restored, test open/edit/save/export on copies, and deploy an explicitly approved migration if needed. No silent migration or implicit schema upgrade: `project.upgradeTracks` is an explicit typed action, not an automatic load side effect. Preserve opaque project fields and keep a rollback path. Install the exact GitHub release tarball documented in README, verify SHA256SUMS, and keep the consumer lockfile. Subsequent alphas receive new immutable versions; neither public availability nor a passing doctor certifies your receiving server. Report issues through the public repository with sanitized reproduction data.
