# Contributing

Public testing alpha. Open an issue with the exact SDK version, sanitized `editdock doctor` JSON, OS/Node version, minimal generated-media reproduction, and expected versus actual result. Never include tokens, private media, identifying filesystem paths, or confidential project files. For changes, keep browser imports separate from Node rendering; avoid demo HTTP hosts and new runtime dependencies without review. Run `npm ci`, `npm run build`, `npm run typecheck`, and `npm test` before proposing a patch. Keep lockfiles pinned, add focused tests, and do not rewrite published alpha tags or silently migrate project data. Security-sensitive disclosures should avoid posting exploit details or private data to a public issue; contact the maintainers privately through an established secure channel first.
